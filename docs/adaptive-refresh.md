# Adaptive refresh and host politeness

Background ticks query an index on `(autoMuted, archivedAt, nextSyncAt)` for due subscriptions. The additive SQLite/Postgres migration is pure DDL and leaves new scheduling columns NULL for legacy startup adoption. The first background observation of a NULL schedule persists a Prisma Date, then defers fetching: the later of the last fetch plus the feed's interval (so adoption never refetches a fresh feed early) and a stagger over the next 15 minutes using a deterministic hash of the feed ID (which spreads overdue and never-fetched feeds). This applies to new/restored/edited feeds too; explicit refresh bypasses initialization. NULL schedules sort first on both providers. No Article bookkeeping writes are involved. `nextSyncAt` is persisted because querying and calculating every feed on every tick would keep waking the database. App-side initialization changes only Feed.nextSyncAt, guarded by nextSyncAt IS NULL so concurrent manual scheduling wins.

After a successful fetch, including a cheap conditional GET/304, the last 40 stored publication timestamps determine the median interval. Duplicate timestamps and clusters closer than half the median gap (at most five minutes) do not inflate publication frequency. Missing publication times fall back to creation time. Future/invalid times are ignored. Half the time since the most recent publication provides an idle floor, preventing old backfill dumps from triggering rapid polling. New/single-item feeds start at 60 minutes. Estimated cadence is stored separately for display.

Automatic intervals are clamped to 15 minutes–24 hours. `FEED_MIN_REFRESH_MINUTES` and `FEED_MAX_REFRESH_MINUTES` configure these bounds. Existing category/user interval preferences remain a minimum; explicit per-feed minutes take precedence over cadence and inherited preferences, with a five-minute floor unless FEED_MIN_REFRESH_MINUTES explicitly sets a higher server minimum. Explicit/inherited values above the automatic ceiling remain respected. Existing Google News minimum and exponential failure delays are retained when persisting schedules. Empty feed interval means Automatic. Feed management's edit dialog displays the estimated publications/day and next fetch time. Interval edits invalidate that feed's schedule. Changes to category/global preferences take effect on the next scheduled fetch (at most the current interval).

Reader boot uses due selection and the shared host gate. Manual single-feed refresh and user Refresh all bypass due times; archived and auto-muted feeds remain excluded from bulk refresh. There is currently no WebSub subscription state in FeedFerret, so there is no reliable push-capability signal to apply a maximum interval to.

The shared in-process background host gate permits one feed fetch per hostname and spaces request starts by 2 seconds (`FEED_HOST_SPACING_MS`). Different hosts can run concurrently, across users. Background runs group feeds by host and rotate ready hosts through the worker pool. Spacing waits happen outside worker slots; each host drains sequentially within the run budget. Busy hosts from another run are retried in this run, and only budget leftovers receive deferred schedules. For example, at two-second spacing and a 240-second budget, an otherwise idle host can fetch 120 subscriptions rather than one. The per-user reader-boot sync (`POST /api/sync`) uses the same queues with a 30-second budget, because the client waits on it; its leftovers keep staggered schedules for the server-wide run. 429 and explicit Retry-After defer host work; plain 503 defers the affected feed and pauses that host's feed queue for the rest of the run, without marking discovery/full-text callers rate-limited. These deferrals occur without increasing feed failures, triggering error notifications, or auto-muting. Retry-After delta seconds and HTTP dates are honoured (existing seven-day sanity cap), with exponential local backoff otherwise. Successful probes clear expired host failure records while preserving active Retry-After quotas. 403 is feed-specific: retries start at 15 minutes and grow with the duration of the blocked streak, capped at the configured automatic ceiling; an HTTP 403 attention code makes Health show blocked, without penalizing sibling feeds. Full-text 403 retains its two-minute page-fetch backoff and never blocks feed polling. Persisted feed deferrals are capped at the configured refresh ceiling (24 hours by default), while the in-process host quota retains the full Retry-After window. Deferred nextSyncAt survives restart; host gate/backoff state does not. Manual fetches bypass the spacing gate but rate-limit responses still defer without feed failures. All network access remains in the existing safeFetch fetchers.

The gate applies to feed fetch operations (including their parser), not to all article/full-text HTTP requests or redirect destination hosts. Multiple app replicas have independent gates; global distributed politeness would require a shared lease store.

Rollback: revert the application change; leave the additive columns/index in place. No destructive down-migration is required.
